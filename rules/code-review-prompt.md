# 深度代码审查 Prompt

> 从最小审查（min）到最大审查（max）的分级模板。根据变更范围选择对应级别。

## 审查级别

| 级别 | 适用场景 | 维度数 | 预计耗时 |
|------|----------|--------|----------|
| **Min** | 单文件小修复 | 3 | 5 min |
| **Standard** | 功能迭代（≤5 文件） | 6 | 15 min |
| **Max** | 发版前全量审查 | 10 | 30+ min |

---

## Min 审查（3 维度）

```
请对以下变更执行 3 维度审查：

1. **正确性**：逻辑是否正确？边界条件是否覆盖？
2. **防御性**：null/空/NaN/越界是否有守卫？
3. **一致性**：与现有代码风格、命名、架构是否一致？

输出格式：
- P0（必须修复）：会导致崩溃/数据错误
- P1（建议修复）：潜在风险
- P2（改善）：可读性/性能优化
```

---

## Standard 审查（6 维度）

```
请对以下变更执行 6 维度并行审查：

1. **正确性**：算法逻辑、边界条件、数值精度
2. **防御性**：null/NaN/Inf/空集合/越界守卫完整性
3. **安全性**：注入、路径穿越、信息泄漏、资源耗尽
4. **一致性**：架构分层、命名规范、文档同步
5. **性能**：O(N²) 退化、不必要分配、缓存缺失
6. **测试覆盖**：新增代码是否有对应测试？边界是否覆盖？

输出格式：
- 按 P0→P3 分级
- 每项包含：文件:行号 | 问题描述 | 修复建议
- 最后给出总结：通过/有条件通过/需返工
```

## Max 审查（10 维度）

```
请对本项目执行发版前全量深度审查，覆盖以下 10 个维度：

### 维度清单

1. **算法正确性**
   - 数值算法与参考实现（scipy/numpy/MathNet）一致
   - 边界条件：空输入、单元素、全等值、极大/极小值
   - 浮点精度：容差选择合理，无灾难性抵消

2. **防御编程**
   - 每个 Public 入口的参数守卫完整
   - NaN/Inf/null/空集合 不静默传播
   - 异常过滤器排除不可恢复异常
   - 无裸 catch / bare except

3. **安全**
   - 路径验证（沙箱/穿越/符号链接）
   - 输入消毒（SQL 参数化/HTML 转义/正则超时）
   - 无敏感信息泄漏（连接串/密钥/traceback）
   - 资源上限（内存/时间/递归深度）

4. **架构合规**
   - 层级依赖方向正确（无反向/跨层调用）
   - 接口契约未破坏（签名/返回值/异常行为）
   - 新增模块已注册到路由/调度表

5. **文档一致性**
   - api-reference 签名与代码一致
   - user-manual 示例输出与实际一致
   - 函数计数/模块计数准确
   - 无孤立链接

6. **测试完备性**
   - 新增代码有对应测试
   - 边界/退化输入覆盖
   - 交叉验证无自校验（check(X,X)）
   - 差分测试路径一致

7. **性能**
   - 无 O(N²) 可优化为 O(N log N) 或 O(N)
   - 热路径无不必要内存分配
   - 大集合操作使用流式/分批处理
   - 缓存策略合理（无过期/无竞态）

8. **错误处理**
   - 错误信息对用户有意义（中文/可操作）
   - 不暴露内部实现（traceback/堆栈）
   - 优雅降级（部分失败不丢全部结果）
   - 资源清理（finally/using/with）

9. **兼容性**
   - 跨版本兼容（.NET Framework / .NET 8 / Python 3.10+）
   - 跨平台兼容（Windows/Linux，如适用）
   - 依赖版本约束合理（仅下限，避免上限冲突）

10. **工程规范**
    - 无死代码/未使用导入
    - 命名一致（同一概念同一名称）
    - 注释解释"为什么"而非"是什么"
    - commit 粒度合理（一个逻辑变更一个 commit）

### 输出格式

对每个发现：
```
[P{级别}] {文件}:{行号}
  问题：{描述}
  影响：{后果}
  修复：{建议}
```

最后输出：
- 统计：P0×N + P1×N + P2×N + P3×N
- 结论：🟢 可发行 / 🟡 修复 P0+P1 后可发行 / 🔴 需返工
```

## 审查前置条件

执行审查前确认：

- [ ] 已加载项目 AGENTS.md（了解红线和架构）
- [ ] 已加载对应 skills/（了解语言陷阱）
- [ ] 已运行全量测试（确认当前基线）
- [ ] 已查看 `.claude/exemptions.md`（如存在，了解已知豁免）

## 豁免（exemptions）规则

> `.claude/exemptions.md` 是**已知风险豁免登记表**（如有）：记录「已确认接受、暂不修复」的审查发现。

- **登记格式**：`- [P1] {文件:行号} {问题} — 接受原因 / 到期版本或日期`
- **P0 不可豁免**：会导致崩溃/数据错误的发现必须修复，登记无效
- **P1 可豁免**：需写明接受原因 + 到期版本（到期后审查必须复查）
- **登记即责任**：豁免项进入「下次审查必查清单」，不可静默消失
- 无豁免文件 = 无豁免项，审查输出 P1 一律要求修复

## 审查后行动

| 发现级别 | 行动 |
|----------|------|
| P0 | 立即修复，不可跳过（豁免登记无效） |
| P1 | 本次修复，除非已按上述规则登记豁免 |
| P2 | 记录到改进计划，下次迭代处理 |
| P3 | 可选修复，不阻塞发版 |
